## Product (locked)

Two-sided salon reservation PWA for Sarajevo. Customer picks service(s), optional worker, and a preferred **day** and an optional quarter. The salon profile request is the picker (`Pošalji zahtjev`). Scripted salon-profile chat (Epic 10) is not offered on that profile. A request creates `requested`. A customer cannot send another request at a salon for a service already on a different live booking of theirs (`requested`, `time_proposed`, or `confirmed`) on that preferred day. Picker and the request modal stay open: **Već imaš ovu uslugu tog dana.** Ask other time and reschedule fail the same way on the target day. Declined, cancelled, and phone bookings do not count. Not Zauzet. Owner accepts a named worker’s preferred time, assigns a free worker when the guest left no preference but did pick a time (that confirms, and the guest is not asked), or counter-proposes. A day with no quarter stays `requested` until the owner counter-proposes on that same day. Status: `requested → confirmed` (accept or assign worker), `requested → declined` (owner decline), or `requested → time_proposed → confirmed | declined` (counter-propose). A phone booking is born `confirmed` for a caller who is not a customer, and its start is not already past in Sarajevo. A confirmed booking may become `cancelled` (customer cancel, late is a warning, not a hard block; or the owner ends a phone booking before the start, no trust counters).

## Architecture (locked)

See `docs/architecture/`. Short version: Laravel + Lighthouse GraphQL + MySQL + Redis + Reverb, one React TypeScript PWA, Sanctum cookies, same origin via Nginx. Slim Docker Compose (`php` + `vite` + `mysql` + `reverb`) lives in `esyres_app/`; nginx, redis, queue worker, and mailpit are not written yet.

Do not invent a different stack. Do not expand the scaffold into product features unless the user asks.

**Local verify** uses the frontend-only classifier, then one of the two command sets.

**Frontend-only classifier (fail-closed):** From the git root, union changed paths: untracked (`git ls-files --others --exclude-standard`), unstaged (`git diff --name-only`), staged (`git diff --cached --name-only`), and this branch vs `main` (`git diff --name-only main...HEAD`; if `main` is missing, `origin/main`). Skip Behat only if **every** path under `esyres_app/` in that union is under `esyres_app/frontend/`. Git-root `docs/`, `DESIGN.md`, `refs/`, `.cursor/`, and `AGENTS.md` do not trigger Behat. Any other `esyres_app/` path (PHP, `features/`, `graphql/`, Composer, Compose, app README, …) → full Behat. Do not skip from a story label. Nearby UI stories are not a class.

**When skipped:** do not `compose up`, start php/mysql, or run `php artisan --version`. From `esyres_app/frontend/`: `npm run typecheck`, `npm run test`, `npm run build` (host npm). `docker compose exec -T vite npm run …` only if that container is already up. No Playwright as a Behat substitute. Layout stays merge-visual (playbook **UI ready rule**).

**When Behat runs** (classifier fails, or the human asks for Behat / `/run-tests --suite`): from `esyres_app/`: `docker compose up -d`; `docker compose exec -T php php artisan --version`; `docker compose exec -T php vendor/bin/behat --format=progress --stop-on-failure` (Behat loads `.env.behat`, DB `esyres_test` only — never `esyres`); frontend `typecheck` / `test` / `build`. Never `docker compose run` for verify or servers; reuse :5173/:8000/:8080. See `esyres_app/README.md`. Backend gate is Behat, not `php artisan test`. Behat flags are CLI-only (same flags on `--suite owner|guest`); do not put them in `behat.yml`. A green run still means the full selected suite passed.

**Cloud Agent verify:** Frontend-only: host npm from `esyres_app/frontend/` only — no host PHP/MySQL. If Behat runs and `docker` is missing or dockerd is nested (apt-install `docker.io` inside the VM), do **not** start Compose MySQL that way — Behat becomes ~14× slower. Same as STORY-36: host PHP + host MySQL, still `.env.behat` / `esyres_test` only. Do not `migrate:fresh` or seed `esyres`. Do not `compose down -v`.

Cloud Agent: frontend-only is host npm; if Behat runs and Docker is missing or nested, host PHP + host MySQL (STORY-36) — do not apt-install dockerd; Behat still `esyres_test` only. Clear fog with **grilling** rounds; user starts `/grill-with-docs` so glossary and ADRs land on disk. `/new-story`, `/grill-me`, and `/grill-with-docs` accept opt-in `no-human-grilling` / `no-human-review` on product persist (one incremental `STORY-xx`; refuse flags on a full MVP; process/stack no-ops). Attended sequential drain is `/start-building-stories` (print what-next, then Local story-loop for Recommended; after merge, continue) — still one story → one PR, not an unattended gauntlet. UI stories: ready on machine gates; visual review is you at merge (no PR screenshot gate). See playbook **UI ready rule**.
