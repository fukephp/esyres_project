# Self-serve create salon; owners are not invite-only

Instant ownership (the submitter lands on the owner panel at submit) is superseded by `docs/adr/0051-first-salon-waits-for-admin.md`. Same-account, name-only create stands.

A public “Get your panel” CTA on the homepage needs a real owner path, not a waitlist. The CTA is a link to `/create-salon` (not `/signup`, not under `/owner`): AuthShell, then email verify if needed, then a name field on a sparse Design-1 form (empty top-nav slot, no homepage hero/footer). A signed-in user with verified email submits a salon by name only (same `users` row; same defaults as today’s provisioned salon: closed week, cancel 24h, empty catalog). They do not own it, and they do not land on `/owner`, until an admin approves it (`docs/adr/0051-first-salon-waits-for-admin.md`). If they already own a salon, the homepage CTA is Panel → `/owner`, and `/create-salon` redirects there. Email verification is required to create (Decision 6; local skip unchanged). Rejected: founder-only provision, a Formspree/waitlist, a second owner account type, and a homepage-inline salon factory. Public waitlist stays out. Shared top-nav chrome is `docs/adr/0029-shared-top-nav.md`.
