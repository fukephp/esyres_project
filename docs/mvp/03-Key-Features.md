# Key Features

*This file separates what's locked for MVP from what's explicitly deferred to Phase 2, per current decisions.*

## Customer-Facing (MVP)

- **Homepage** — typed `/` is a permanent Bosnian page: shared top-nav with the homepage slot (logo, Prijava/Registracija, Get your panel → `/create-salon` or Panel → `/owner` as the black primary), the existing hero + Pronađi salon, simple footer. Not a login wall. When Prijava/Registracija is open, hide hero + footer; the auth `h1` is Rezervacije; form stays left. Pronađi salon goes to `/salons`. `/salon/:id` and the QR sticker skip the homepage page. No persist-seen, no separate marketing site, no owner waitlist.
- **Top-nav** — one full-bleed Cal bar (brand → `/`, per-route native slot) on `/`, `/salons`, `/salon/:id`, `/create-salon`, `/bookings`, and as an overlay on `/owner`. Guest routes share one inner column (~1200px, Design 1) so nav inner and `main` align; owner overlay inner stays unconstrained. Discovery and salon share Moje rezervacije in the slot (not Prijava/Get your panel). Logged-in with a person name: `Dobrodošli, {name}` (text, not a link; never email) in every of those slots. Create-salon is greeting-only when named, empty otherwise. Logged-in Odjava is the Design 2 destructive pill (`error-strong` fill, white label, same size as Panel, `rounded-full`; press darker, no hover, one tap) on `/`, `/bookings`, and the owner phone header. The `md+` owner rail uses an exit icon in the same `error-strong`. Homepage order: greeting → Moje rezervacije → Odjava → Panel. Discovery/salon: greeting then Moje rezervacije. `/bookings` and owner overlay: greeting + that Odjava. No name → no identity text. Prijava/Registracija stay text. OwnerNav stays (Saloni → `/owner/salons`; Postavke → `/owner/settings`).
- **Discovery home** — `/salons`; no login required; geolocation-based "salons near you," falling back to "Popular in Sarajevo". Idle is a short **discovery teaser** (first few listed salons as cards). A **discovery chip**, name search (`Ime salona`), or show all opens **discovery results** (hairline rows). Teaser and results show name, today’s busy-level, that salon’s service category names, and address when set. Only **listed** salons (one open weekday and one service). Brand in the top-nav links home. See `docs/adr/0030-discovery-teaser-then-results.md`.
- **Salon Profile** — address when set (omit if missing; text line, no maps in this slice), working hours (read-only seven-row list in the left column; weekday, hours and break, or Zatvoreno; rows are not buttons; no helper; no hours rail), service list grouped under the owner’s service category names (heading per group with ≥1 service; `md+` jump list when ≥2 groups; browse-only on the page), and a busy-level badge (🟢/🟡/🔴 — see below). One `Pošalji zahtjev` after the hours list and before Usluge (hidden when the salon has no services) opens a picker **modal** (salon name + muted weekday+date when a date is known; services, worker, Danas / Sutra / Drugi dan, quarter starts, send). It does not send on open. `md+` sticky right aside stays empty. Pitaj salon is not on the profile and the chat dialog does not open from it. Zatvori is the only dismiss. The native date on Drugi dan, backdrop, Escape, and send leave the modal open. Photos and optional maps link-out stay later; no in-app map SDK.
- **Busy-Level Indicator** — coarse signal of how booked a day is, shown on the salon profile and on discovery teaser/results. The day badge stays coarse. Pošalji zahtjev, not this badge, shows which quarter starts are Zauzet.
- **Service Selection** — multi-select, durations/prices stack automatically.
- **Worker & Date/Time Selection** — pick a specific worker or "no preference"; on Pošalji zahtjev pick Danas, Sutra, or Drugi dan, then an optional quarter start for that day (Zauzet when the service range overlaps an occupying booking). Drugi dan is a native date (`min` today) and then the same pills. On an open day, Send works with no quarter selected, with the muted line `Možeš poslati i bez vremena.` A closed day cannot send. An open day whose quarters are all Zauzet or past can still send with no time. A tapped quarter still sends that time. No typed time on that path. A logged-out guest signs in inside the modal before the form. This is the **primary** booking CTA on the salon profile (`Pošalji zahtjev`).
- **Salon Booking Assistant (scripted chat)** — not on the guest profile (STORY-89): no Pitaj salon card, and the chat dialog does not open from `/salon/:id`. The assistant contract remains for Epic 10: guided steps (service → worker → day → 1–3 suggested preferred times → confirm), Bosnian, live salon data only, same `createBooking` and send gates as the picker. Unknown → says it does not know; may ping the owner; guest does not wait. Already-verified users confirm in one step.
- **Registration / login** — email + password. Register requires person name (Ime i prezime, GraphQL `name`) as the first field; login has no name field. Guest browse has no login wall. Homepage top-nav slot offers Prijava/Registracija (same `AuthShell`); request submit and My Bookings still have it. AuthShell (and panel email-verify) shows a place heading: **Rezervacije** on customer shells, **Panel** on `/create-salon` and `/owner*` (logged-out owner must not use queue/chat/stats titles for that). Email verification is required before a request can be sent (and before owner routes or create salon). Phone is optional at register (encouraged); **phone OTP is required to send a request and to respond to a counter-proposal**. Verified phone also enables OTP as an alternate login. `phone_verified_at` is captured now; reward-badge **display** is Phase 2.
- **Send Request** — creates a `requested` booking with a preferred date and an optional quarter. A missing quarter does not occupy a clock and still counts toward that day's busy-level. A chosen quarter holds no clock slot yet either, and is counted the same way. Picker and assistant both produce this row. A customer cannot send when any chosen service is already a **same-day service** on a different live booking of theirs at that salon (`requested`, `time_proposed`, or `confirmed`). The overlay stays open: **Već imaš ovu uslugu tog dana.** Ask other time and reschedule fail the same way when the target day already has that service on a different live booking. The same booking may still move. Declined, cancelled, and phone bookings do not count. Not Zauzet.
- **Time Proposed screen** — Approve / Reject / Ask for a different day or time (shown only when owner counter-proposes). Ask-other-day-or-time **reopens the same booking** (`requested` + new preferred date/time); it does not spawn a second request.
- **My Bookings** — list of requests by status (Pending / Time Proposed / Confirmed / Declined); cancel/reschedule confirmed bookings.
- **Reschedule** — original confirmed booking stays untouched and protected until a new proposed time is approved.
- **Cancel** — owner-configurable notice window; late cancellations get a warning, not a hard block.
- **Favorites** — save salons, including auto-bookmarking via the QR Reconnect Loop (see below).
- **Notifications** — web push + SMS fallback for status changes (time proposed / confirmed / declined); email for reminders (day-before/hour-before).

## Owner-Facing (MVP)

- **Reservation Inbox / Pending Requests Queue** — sorted by upcoming/requested day, soonest first; shows each guest's preferred date and time; near-expiry visual urgency cues; reschedule requests visually tagged.
- **Zahtjevi (month navigator + selected-day list)** — one full-width Cal card on `/owner`: month grid left (`md+`; stacked above on phone) with **occupying-only** worker-colored dots, and a **selected-day list** (pending till-pile, then soon occupying, then the rest including `time_proposed` tagged Predloženo vrijeme, plus titled Pauza / Zatvoreno rows). Occupying rows show the **current job** (service snapshot names + worker). The owner **accepts** a preferred time in one tap or **counter-proposes** from Request Detail (sets `time_proposed`, not `confirmed`). A counter-proposal **holds that slot** until confirm, decline, or expire. `requested` does not occupy a clock slot and has no month dot. Not a guest month-and-pills widget. No 15-minute worker board. No drag. A **Telefon** button opens a phone-booking modal over Zahtjevi for the salon already in context (phone sheet / `md+` card). `/owner/phone` redirects to Zahtjevi and does not open it.
- **Zahtjevi pending jump** — on Zahtjevi only, both Prikaz, phone and laptop, a button in the header action row before Telefon: **Na čekanju · {n}**. `n` is pending rows for this salon on any day (requests plus reschedule overlays). Count `0` hides it. Click sets `?date=` to the earliest pending day (past included); already there, the next pending day, then wrap. Several rows on one day are one stop. The week that contains that day follows. Accept, decline, and counter-propose stay the actions on that day. Not on Zapisi or Request Detail.
- **Zahtjevi confirmed progress** — each confirmed card on Zahtjevi (Kalendar, Kanban **U toku**, Kanban Potvrđeno, and an ended confirmed card in Završeno i otkazano) shows the elapsed share of its occupied range on the Sarajevo clock. The track is always visible. Empty before the start, full at the end, recomputed once a minute. No percent. An in-progress reschedule still measures the original range. A no-show stays confirmed and keeps the bar. Pending, time-proposed, declined, and cancelled cards have none. Zapisi, Request Detail, and the homepage mock have none. The week grid has no now-line.
- **Kanban columns** — Zahtjevi and Zapisi Kanban, in order: **U toku** (`confirmed` whose occupied range contains now, Sarajevo), **Zahtjevi**, **Predloženo**, **Potvrđeno** (confirmed, not started), **Završeno i otkazano** (declined, cancelled, and confirmed whose end has passed). Phone bookings and no-shows follow that clock. Membership recomputes once a minute with the progress bar. Two checkboxes on the board, stored on the person account, default both visible, shared by both screens: hide **U toku**, hide **Završeno i otkazano**. Hidden cards are not folded into another column. Kalendar is unchanged.
- **Assign worker** — on a `requested` row that has a preferred time and no worker, worker-name taps on the Zahtjevi pending card (both Prikaz) and inside Request Detail. A tap confirms at the guest’s time with that worker. Only workers free for the whole range are listed (same overlap as accept; hours are not re-checked). Nobody free: no taps; Predloži and Odbi stay. The guest is not asked. Zapisi has no inline taps.
- **Owner menu** — every owner route. `md+`: a black rail, collapsed to icons by default (mark → `/`, outline icons for Zahtjevi, Zapisi, Chats with the count badge when the Chat switch is on, Statistika, Saloni, Postavke, and an icon Odjava). The Chat icon, phone tab, and badge are omitted while Chat is off (the default), including on the loading shell. A toggle above Odjava expands the rail in the layout and shows those labels; Odjava stays an icon. Names: **Proširi izbornik** / **Sklopi izbornik**. This browser remembers; nothing saved means collapsed. The loading shell uses the saved width. Active link is the light pill. The salon switcher, or the salon name when they own one, sits on the greeting row before Telefon. Phone header stays (text Odjava, Statistika text link). Phone tabs are the same icons the rail shows, without visible labels.
- **Phone booking** — the owner writes a confirmed booking for a caller who is not a customer, in modal steps: one or more services, **Danas** / **Sutra** / **Drugi dan**, a quarter-hour start inside working hours (not in or spanning the break; earlier today is allowed; at least one worker free), a worker name tap, a caller name, an optional phone, and an optional note. Born `confirmed`. Occupies like any confirmed booking. Never linked to a user. No push, SMS, or email. After save, Zahtjevi opens on that day.
- **Request Detail** — `/owner/requests/:id` is a modal over Zahtjevi or Zapisi (phone sheet / `md+` card). The card inside keeps the hairline Cal box: in-card customer name + mode clock; form / read / bounce. **Zatvori**, backdrop, and Escape close it and return to the board the owner came from (a pasted link returns to Zahtjevi on that booking’s day; from Zapisi, the same day, origin, and salon). Accept, decline, assign worker, and counter-propose leave the modal open on the updated card. Salon switcher stays hidden while it is open. No **Nazad**. Tap a pending Predloži or an occupying row still opens this URL. Accept preferred time, decline, or counter-propose via a form (the only propose path); occupying is read-only except a phone booking; bounce stays in that card. Assistant-originated requests are tagged; a collapsed transcript is attached (why they asked for Saturday 14:00). A phone booking shows the caller name, phone, note, and the saved choices, and a two-step owner cancel before the start (becomes `cancelled`, no trust counters, no reason). No other-bookings memory on a phone booking. No-show after start stays `confirmed` and increments the salon counter only. Not a `max-w-xl` empty column, not the salon-edit panel, not a full-page card.
- **Zapisi** — OwnerNav list for the salon in context. One day, every status, filtered by origin (Gost / Asistent / Telefon) and day. Rows show time, origin, name, services, and status. Each row opens Request Detail. In-flight chats stay on the chat tab.
- **In-flight chat tab** — not owner home. Badge for conversations that have not yet become a request. Optional **Take over**: guest waits only after the owner taps it. After hours / DND: take-over off; assistant always finishes to `requested`. No auto-page on every chat. Owner-only; workers are not users.
- **Decline** — optional reason field shown to the customer.
- **Salon catalog** — `/owner/salons`. Stacked hairline boxes of shops the owner owns (even at one shop); each box shows name + **open now** from working hours and **Uredi** (only tap into salon edit; name is not a link). Plus under the `Saloni` title is the only add (`/owner/salons/create`). Not listed, not a toggle, not a table. OwnerNav **Saloni** on every owner route. Not the salon switcher and not discovery.
- **Owner settings** — `/owner/settings`. OwnerNav **Postavke** on every owner route. **Prikaz**, a **Chat** switch (default off; hides the Chat tab until turned on; stored threads stay), and password (current / new / confirm); muted read-only email; stay signed in after a password change. Not salon edit. No `?salon=`. No customer settings twin.
- **Add salon** — `/owner/salons/create` (already an owner). Name and address both required. Lands on salon edit. Does not change `/create-salon` (first shop, name only).
- **Salon edit** — `/owner/salons/:id`. Four exclusive chips (Informacije / Radno vrijeme / Usluge / Radnici); one panel at a time; land and refresh on Informacije. Full-width hairline box in owner `main`. Name and address (cannot blank), optional salon description, optional main image, and an optional gallery of extra images (Informacije; images upload/remove immediately; guest profile and public GraphQL stay photoless this slice), full weekly hours (days, times, optional break, cancel window; Radno vrijeme is a one-column exclusive accordion, land all collapsed), create/edit service categories and services (Usluge: selected group + its services; rename; delete category only if empty) and workers by name. No delete of services or workers. No worker↔service matrix. DND stays on chats. Coordinates and reschedule cap stay off this page.
- **Working Hours & Availability Settings** — edited on salon edit (weekly template + cancel window). Radno vrijeme: one column of weekday summaries; at most one day editor open. Holidays and reschedule-cap UI stay off this page. Default reschedule cap remains 1 in-progress overlay per booking.
- **Service & Pricing Management** — add/edit owner-named service categories and services (duration, KM price) on salon edit; default service duration 30 min. A service belongs to exactly one category. No delete of services; delete a category only when empty.
- **Staff/Worker Management** — add/edit workers by name on salon edit; each worker has a stable color on Zahtjevi occupying dots and rows. Workers inherit salon hours (no per-worker shift editor or vacation calendar at MVP). Worker↔service assignment is later, not this slice.
- **Salon switcher** — an owner may have more than one salon, each a separate customer-facing profile (hours, workers, QR, busy-level). `?salon=` on queue, chats, stats, and Zapisi. Not a chain “one brand, many locations” product.
- **Request Detail memory** — on `/owner/requests/:id`, other confirmed bookings for this customer at this salon (newest first; date, service snapshot names, and **Nije došao** when that row is stamped). The open request is excluded. Cancelled, declined, and still-requested stay out. **Nije došao** on the open card calls `markNoShow` (after start, status stays `confirmed`, one tap, no undo). No notes, no QR-visit chrome, no `/owner/customers`.
- **Basic Stats** — bookings per week, busiest hours/days, cancellation rate, day-level busy %, QR scan and scan→verified-visit stats.
- **Notifications** — web push, real-time, for new requests, customer responses, and reschedule requests.

## Shared / Cross-Cutting (MVP)

- **QR Reconnect Loop** — the existing front-counter acquisition QR code gets a second job: a ~7 day guest cookie holds the last scanned salon; once a customer verifies, the scan silently bookmarks the salon as a Favorite and records a QR visit. That visit stays data (Statistika), not Request Detail chrome. No second sticker, no popups.
- **Trust signal data capture** — response-time timestamps, no-show/cancellation counters, QR scan events, and verification status (`email_verified_at`, `phone_verified_at`) are captured from MVP launch, even though badge display is Phase 2.
- **Owner onboarding** — self-serve **create salon** on the same account (`/create-salon`, name only). An owner **adds** another shop from the salon catalog (`/owner/salons/create`, name and address). Not invite-only. Not a waitlist. Not a second user type.
- **Multi-service, multi-category salons** — a salon may have several owner-named service categories from day one. A service belongs to exactly one. Not a locked HAIR / MAKE_UP / MASSAGE enum. Discovery chips stay Kosa / Šminka / Masaža until a later story. See `docs/adr/0033-salon-service-categories.md`.

## Explicitly Phase 2 (not MVP)

- Trust badge **display** UI (data capture happens at MVP; display is deferred).
- Viber and/or WhatsApp messaging (owner re-engagement / marketing outreach) and Instagram DM as assistant channels — same booking contract later; not v1. Channel choice not decided.
- LLM / free-form NLU for the assistant (v1 is a scripted flow; an LLM may parse messy text later without changing `createBooking`).
- Native app (App Store presence).
- Customer referral incentive mechanic.
- Reviews/ratings system.
- Worker self-service login.
- Buffer time between bookings, per-worker off/vacation days / hourly shifts.
- Chain multi-location (shared workers/services across sites), receptionist/manager roles, waitlists, gift cards, group bookings, package deals.
- Public owner waitlist / Formspree / `/invite`, public pricing page, Awwwards/GSAP company site, sibling `marketing/` Vite app.
